# История изменений

В этом файле собраны изменения Nonead DSH Desktop, заметные пользователю. Каждый выпуск синхронно повышает версию в обоих рабочих пространствах настольной версии (`nonead-dsh-desktop` и `dsh-plugin-desktop-beta`); версия также попадает в имена установочных пакетов, ответ конечной точки обновлений и сопоставление прямых ссылок на загрузку, и все три места должны совпадать.

Соглашения о поддержке:

- Каждый выпуск добавляет по одной записи на язык (`CHANGELOG.md`, `CHANGELOG.en.md` и версии ja/es/fr/de/ru/pt) и обновляет хеши Git blob, записанные в `CHANGELOG.i18n.yaml`, иначе `corepack yarn check:bilingual-docs` завершится ошибкой.
- Записи описывают только то, что может заметить пользователь, и граничные изменения, о которых должны знать сопровождающие; чистая переработка кода отдельной записи не получает.
- Более ранняя история хранится в Git-тегах (`v1.7.3`, `v2.0.7`, `v2.0.8`, `v2.1.3`, `v2.1.4`, `v2.1.5`) и в журнале коммитов.

## 2.2.10 — 2026-11-12

Рантайм обновлён до DSH 0.2.2-rc.2 с адаптацией несовместимых изменений нового ядра:

- Рантайм: встроенный DeepSeek Harness переходит с 0.2.2-rc.1 на **0.2.2-rc.2** (upstream-коммит `ddac96760`, 374 пакета пересобраны в vendor, 24 патча для десктопа перебазированы). `dsh-experimental-agent-team` переименован в `@deepseek-ai/dsh-agent-team`; такие пакеты, как `dsh-error`, стали peer-зависимостями, которые приложение объявляет явно.
- Мост: мост Agents Anywhere остаётся на линии 2.1.0, чей peer-диапазон старше rc.2; при включении удалённого управления приложение записывает точное исключение версии в `compatibility.json` профиля, и мост продолжает загружаться.
- Встроенные плагины: `@deepseek-ai/dsh-tool-subagent` обновлён до 0.2.2-rc.2 в соответствии с цепочкой зависимостей рантайма; в поставке по-прежнему 27 плагинов.
- Документация: README на восьми языках и `THIRD_PARTY_NOTICES` приведены к новым данным о версии.
- Версия: продукт 2.2.9 → **2.2.10** (оба рабочих пространства десктопа).

## 2.2.9 — 2026-11-10

Среда выполнения переходит на DSH 0.2.2-rc.1, набор встроенных плагинов доходит до 35, а мастер первой настройки рассказывает об этом иначе:

- Среда выполнения: встроенный DeepSeek Harness переходит с 0.2.2-alpha.3 на **0.2.2-rc.1** (коммит upstream `66491b0`, семейство cordis переведено на 4.1.0, schemastery — на 3.19.0). `vendor/dsh-runtime/0.2.2-rc.1` собран заново из локального дерева исходников upstream как 373 пакета, и набор пакетов полностью совпадает с предыдущим выпуском; все 24 патча настольной версии перенесены на новые артефакты, корневые `resolutions` и оба настольных workspace указывают на новую версию, `yarn check:vendored-runtime` проходит для обоих каналов.
- Первичная настройка: шаг «всё готово» в мастере установки больше не перечисляет все плагины подряд, а по категориям объясняет, что даёт этот предустановленный набор; после начала установки, когда доходит очередь каждого плагина, показываются его имя, версия, категория и полное описание, а также благодарность автору — «Спасибо X за этот плагин».
- Встроенные плагины: набор поставляемых плагинов растёт с 30 до **35**, добавлены `@changfenhuang/dsh-genui`, `@deepseek-ai/dsh-tool-subagent`, `@linxin666/dsh-client-ui-task-board`, `@weibaohui/skills-management`, `billion-context`, `dsh-client-auto-continue`, `dsh-cost-meter`, `dsh-markitdown`, `dsh-nonead-prompt-rewind`, `dshmarket`; из встроенного набора убраны `dsh-api-client`, `dsh-design`, `dsh-doc-reader`, `dsh-rewind-plugin` и `@kenz1117/dsh-ui-usage-billing`.
- Обновление плагинов: `dsh-ppt-master` 1.0.8 → 6.1.0, `dsh-config-manager` 0.3.1 → 0.6.0, `@michengai/dsh-skills-manager` 1.2.28 → 1.4.0, `dsh-better-sidebar` 0.28.2 → 0.30.1, `dsh-context` 0.80.3 → 0.83.0, остальные обновлены до последних версий из npm.
- Манифест плагинов: `plugin/manifest.json` переходит на v4, у каждой записи появляются категория и автор — по ним мастер настройки группирует плагины и показывает благодарность.
- Версия: продукт 2.2.6 → **2.2.9** (оба настольных workspace движутся вместе).
- Предупреждение при запуске: Profile без включённого удалённого управления больше не пишет строку моста в свой слой cordis, поэтому `patch: entry "agents-anywhere-bridge-next" not found` не появляется в журнале при каждом старте; Profile с включённой функцией сохраняют прежнюю строку вместе с перенаправлениями упакованной установки.
- Встроенные плагины: `dsh-nonead-ursim` обновлён до **0.3.15** с описанием для симуляции (раньше оно было побайтно равно описанию плагина реального робота `dsh-nonead-universal-robots`, что подталкивало ставить его для работы с железом).
- Встроенный мост: мост Agents Anywhere переходит на линию **2.1.0** (тег `v2.1.0`). AA требует обновлять плагин вместе с MINOR-обновлением Desktop/Connector, иначе локальное подключение остаётся в ожидании. Артефакт по-прежнему — собственная сборка desktop-варианта, патч устойчивости коннектора пересобран под 2.1.0.
- Обновления плагинов: `@michengai/dsh-archive-manager` 1.3.1, `dsh-config-manager` 0.7.0, `dsh-context` 0.83.1, `dshmarket` 1.73.17.

## 2.1.17 — 2026-10-24

Пакет исправлений по итогам аудита (26 исправлений, перечислены ниже):

- Помощник по восстановлению: когда автоматический экспорт диагностики и действие пользователя одновременно обновляли один и тот же документ, первая навигация завершалась ошибкой `ERR_ABORTED`; на пути без действия пользователя эта ошибка могла быть усилена режимом fail-loud до полного выхода приложения. Теперь обновления сериализованы, навигация, прерванная уничтожением окна, считается нормальным завершением, а сбои на пути действия только записываются в диагностику.
- Чтение контрольных точек и деградация: файлы manifest и резервных копий открываются, а затем повторно проверяются по inode (`O_NOFOLLOW` + `fstat`), поэтому путь, подменённый между `lstat` и чтением, больше не считается доверенным; повреждённый слот больше не проваливает весь список снимков — он помечается как нечитаемый, остаётся видимым, но недоступным для восстановления на странице восстановления, а ротация использует его как следующую цель перезаписи.
- Запись настроек: `settings.yaml` и `pnpm-workspace.yaml` профиля публикуются через временный файл с последующим переименованием, поэтому прерванная запись оставляет либо старое, либо новое содержимое вместо половины YAML, из-за которой при следующем запуске теряются все настройки.
- Обновления: тела ответов освобождаются на путях превышения размера и ошибки декодирования; macOS отмечает передачу установки до запуска нативного этапа, поэтому выход больше не удаляет пакет, который всё ещё отдаёт локальный feed; выбор «Выход» в окне восстановления, открытом пользователем, больше не считается сбоем запуска (код успеха), тогда как сбои запуска по-прежнему возвращают ненулевой код.
- Хранилища плагинов и состояния: чтение состояния плагинов повторно проверяет inode; сбор устаревших блокировок данных допускает одновременный `ENOENT`; защита от повреждённого состояния теперь проверяет именно тот файл, который защищает; деревья staging среды выполнения, оставшиеся после сбоя, вычищаются перед следующей публикацией.
- Стабильная оболочка: диалог результата проверки обновлений, инициированный из трея, принадлежит главному окну, поэтому его больше нельзя перекрыть и потерять ответ; переключатель Computer Use трактует `cancelled` так же, как `failed`; завершение гостевого браузера ограничено по времени (принудительно через 1,5 с, затем 0,5 с запаса), lease освобождается первым, а `browserRelease` больше не зависает навсегда.
- Магазин сообщества и оформление: прерванный запрос постраничной загрузки больше не оставляет «загрузить ещё» в состоянии загрузки навсегда; оверлей магазина возвращает фокус при закрытии; внедряемый стиль объявляет `data-plugin`, поэтому позже загруженный плагин не может его присвоить и удалить при выгрузке; грамматика имён пакетов совпадает с Host.
- Гейты и CI: `upstream-command-windows` устанавливает зависимости перед `check:layout`; классификация изменений отключает обнаружение переименований, поэтому исходный файл, переименованный в путь документации, не может обойти продуктовые гейты; тест совместимости inspector привязан к корню репозитория.
- Упаковка: `verify:safe-cleanup` стабильной оболочки теперь направляет `TEMP` дочернего процесса Electron в записываемый каталог рабочей области (Electron 44 на этом хосте отказывается создавать каталоги в `%TEMP%`), поэтому предварительная проверка больше не прерывается до создания установщика.

- Патч httpx для AA connector расширен и покрывает новый путь подключения.

Обновления и восстановление:

- Карточка обновления может показывать **описание выпуска**, переданное вместе с ответом о версии; меню трея и нативные диалоги канала Beta также предлагают пункт «Показать полное описание» (метки трея и текст уведомлений обрезаются по правилам платформы), а нативный диалог обновления стабильного канала по-прежнему содержит только фиксированный текст.
- Добавлено действие **пропустить эту версию**: решение сохраняется на диск, поэтому автоматическая проверка по расписанию больше не предлагает пропущенный выпуск.
- Неудачную установку можно повторить, а восстановление позволяет откатиться к **любому сохранённому снимку**, не только к последнему.
- Запуск нативного установщика теперь начинается **до** последовательности выхода, поэтому выход не может утянуть установщик за собой.
- Подпись установщика Windows и проверка издателя были добавлены, а затем **полностью отменены** в `c5896ac`; установщики Windows по-прежнему сравнивают только `ProductName` / `ProductVersion` из ресурса версии PE.

Оболочка настольной версии:

- Позиция и размер окна запоминаются; восстановление выполняется только пока окно всё ещё пересекается с подключённым дисплеем, поэтому отключение монитора не может увести его за пределы экрана.
- Строгая поддержка многоуровневого `.env` дополняет отсутствующие переменные для дочернего процесса Host, не переопределяя существующее окружение.
- Поддерживаются глубокие ссылки `dsh-desktop://` (например, `dsh-desktop://settings/general`).
- Переключатель автозапуска при входе считывает фактическое состояние ОС.
- Циклы чтения-изменения-записи конфигурации профиля теперь выполняются под единой блокировкой записи, поэтому оболочка и менеджер профилей Host не могут молча потерять обновления друг друга.
- Бюджеты повторов для одного экземпляра и одноразовой очистки зафиксированы на трёх попытках; необработанные сбои процесса отрисовки отображаются в области уведомлений.
- `.env` и окружение среды выполнения гостевого браузера передаются корректно.

Магазин и оформление:

- Магазин показывает **предварительный просмотр медиа, отличных от изображений**, и поддерживает **установку плагина по имени**.

Исправления:

## Известные проблемы

- Обновление из приложения в Linux только проверяет версию и никогда не загружает установщик; для обновления загрузите новый AppImage.
- Установщики Windows пока не проверяются криптографически: путь загрузки поддерживает серверный `installerSha256`, но конечная точка версии его не публикует, поэтому сравниваются только `ProductName` и `ProductVersion` из ресурса версии PE.
- Неинициализированный подмодуль `deepseek-harness` приводит к ошибке `corepack yarn check:layout`; обычная сборка, проверка типов и тесты не затронуты.
