# История изменений

В этом файле собраны изменения Nonead DSH Desktop, заметные пользователю. Каждый выпуск синхронно повышает версию в обоих рабочих пространствах настольной версии (`nonead-dsh-desktop` и `dsh-plugin-desktop-beta`); версия также попадает в имена установочных пакетов, ответ конечной точки обновлений и сопоставление прямых ссылок на загрузку, и все три места должны совпадать.

Соглашения о поддержке:

- Каждый выпуск добавляет по одной записи на язык (`CHANGELOG.md`, `CHANGELOG.en.md` и версии ja/es/fr/de/ru/pt) и обновляет хеши Git blob, записанные в `CHANGELOG.i18n.yaml`, иначе `corepack yarn check:bilingual-docs` завершится ошибкой.
- Записи описывают только то, что может заметить пользователь, и граничные изменения, о которых должны знать сопровождающие; чистая переработка кода отдельной записи не получает.
- Более ранняя история хранится в Git-тегах (`v1.7.3`, `v2.0.7`, `v2.0.8`, `v2.1.3`, `v2.1.4`, `v2.1.5`) и в журнале коммитов.

## 2.2.4 — 2026-10-31

Встроенные плагины и установка:

- Встроенные плагины: установщик содержит 30 плагинов, перечисленных на последней странице первичной настройки; «Готово и запуск» устанавливает их, после чего ими можно управлять в разделе «Установленные» магазина плагинов.
- Ход установки: во время установки показываются описание текущего плагина и индикатор прогресса (n/30); неудачный плагин пропускается, остальные устанавливаются, а в конце выводится сводка.
- Список плагинов: компактная раскладка в четыре колонки, помещающаяся на одном экране без полосы прокрутки.
- Гарантия загрузки: после установки проверяются зависимости и список bundle профиля, недостающее дополняется — состояние «установлен, но отключён» больше не возникает.
- Windows ARM64: появился отдельный arm64-установщик, использующий ту же полезную нагрузку, что и пакет x64; встроенная среда выполнения Python / Node / Office остаётся x64-нагрузкой, исполняемой через эмуляцию Windows.

Версия: продукт 2.2.3 → **2.2.4** (оба рабочих пространства настольной версии синхронизированы).

## 2.2.3 — 2026-10-29

Оболочка настольной версии локализована на восемь языков — китайский (упрощённый), английский, японский, испанский, французский, немецкий, русский и бразильский португальский:

- Страница настроек: словари настроек на шести языках (по 125 записей) охватывают магазин плагинов, удалённое управление, окно, браузер и локальную сеть, а также уведомления, поэтому эти разделы больше не откатываются к английскому.
- Интерполируемые строки: одиннадцать диалогов (удаление и переключение профиля, включение, отключение и удаление плагинов, каталог данных и состояние обновления) теперь находят шаблоны `{name}` и подставляют значение, поэтому в шести языках они больше не откатываются к английскому.
- Процесс отрисовки: текст обратной связи при восстановлении вынесен из модуля, импортирующего встроенные модули Node, поэтому сборка native-ui больше не выдаёт предупреждения об экстернализации `node:fs`/`node:path`/`node:crypto`.
- Границы: помощник по восстановлению и средство выбора профиля находятся в общем рабочем пространстве `dsh-plugin-desktop-beta` и по-прежнему доступны только на китайском и английском.
- Версия: продукт переходит с 2.2.2 на **2.2.3** в обоих рабочих пространствах настольной версии.
- Документация: README и CHANGELOG теперь также публикуются на японском, испанском, французском, немецком, русском и бразильском португальском; двуязычный шлюз теперь принимает многоязычные записи (не менее двух документов на запись).

Попробуйте позже.» вместо прежнего названия продукта Next; полоса прогресса загрузки перемещена между надписью «Загрузка обновления x%» и описанием выпуска.

## 2.1.17 — 2026-10-24

Пакет исправлений по итогам аудита (26 исправлений, перечислены ниже):

- Помощник по восстановлению: когда автоматический экспорт диагностики и действие пользователя одновременно обновляли один и тот же документ, первая навигация завершалась ошибкой `ERR_ABORTED`; на пути без действия пользователя эта ошибка могла быть усилена режимом fail-loud до полного выхода приложения. Теперь обновления сериализованы, навигация, прерванная уничтожением окна, считается нормальным завершением, а сбои на пути действия только записываются в диагностику.
- Чтение контрольных точек и деградация: файлы manifest и резервных копий открываются, а затем повторно проверяются по inode (`O_NOFOLLOW` + `fstat`), поэтому путь, подменённый между `lstat` и чтением, больше не считается доверенным; повреждённый слот больше не проваливает весь список снимков — он помечается как нечитаемый, остаётся видимым, но недоступным для восстановления на странице восстановления, а ротация использует его как следующую цель перезаписи.
- Запись настроек: `settings.yaml` и `pnpm-workspace.yaml` профиля публикуются через временный файл с последующим переименованием, поэтому прерванная запись оставляет либо старое, либо новое содержимое вместо половины YAML, из-за которой при следующем запуске теряются все настройки.
- Обновления: тела ответов освобождаются на путях превышения размера и ошибки декодирования; macOS отмечает передачу установки до запуска нативного этапа, поэтому выход больше не удаляет пакет, который всё ещё отдаёт локальный feed; выбор «Выход» в окне восстановления, открытом пользователем, больше не считается сбоем запуска (код успеха), тогда как сбои запуска по-прежнему возвращают ненулевой код.
- Хранилища плагинов и состояния: чтение состояния плагинов повторно проверяет inode; сбор устаревших блокировок данных допускает одновременный `ENOENT`; защита от повреждённого состояния теперь проверяет именно тот файл, который защищает; деревья staging среды выполнения, оставшиеся после сбоя, вычищаются перед следующей публикацией.
- Стабильная оболочка: диалог результата проверки обновлений, инициированный из трея, принадлежит главному окну, поэтому его больше нельзя перекрыть и потерять ответ; переключатель Computer Use трактует `cancelled` так же, как `failed`; завершение гостевого браузера ограничено по времени (принудительно через 1,5 с, затем 0,5 с запаса), lease освобождается первым, а `browserRelease` больше не зависает навсегда.
- Магазин сообщества и оформление: прерванный запрос постраничной загрузки больше не оставляет «загрузить ещё» в состоянии загрузки навсегда; оверлей магазина возвращает фокус при закрытии; внедряемый стиль объявляет `data-plugin`, поэтому позже загруженный плагин не может его присвоить и удалить при выгрузке; грамматика имён пакетов совпадает с Host.
- Гейты и CI: `upstream-command-windows` устанавливает зависимости перед `check:layout`; классификация изменений отключает обнаружение переименований, поэтому исходный файл, переименованный в путь документации, не может обойти продуктовые гейты; тест совместимости inspector привязан к корню репозитория.
- Упаковка: `verify:safe-cleanup` стабильной оболочки теперь направляет `TEMP` дочернего процесса Electron в записываемый каталог рабочей области (Electron 44 на этом хосте отказывается создавать каталоги в `%TEMP%`), поэтому предварительная проверка больше не прерывается до создания установщика.

## 2.1.16 — 2026-10-22

Усиление безопасности и исправления гейтов (результат полного аудита):

- CI теперь запускает классификацию изменений и гейты документации и магазина **со стороны базовой ветки pull request**, поэтому проверяемый код больше не может ослабить собственный классификатор и пропустить все продуктовые гейты.
- Electron fuses ужесточены: обе оболочки закрывают поверхность внедрения через `NODE_OPTIONS` / `--inspect`; стабильная оболочка (`asar: true`) теперь загружается только из `app.asar`, тогда как канал Beta оставляет этот бит выключенным, поскольку поставляет физический каталог (`asar: false`). `runAsNode` должен оставаться включённым — в Windows Host, CLI и shim-обёртки pnpm запускают двоичный файл Electron с `ELECTRON_RUN_AS_NODE`. Оба скрипта `verify-fuses` теперь выводят ожидаемое значение из реальной разметки и проверяют весь набор, поэтому ослабление настроек приводит к ошибке; ранее стабильная оболочка вызывала `verifyElectronExecutableFuses(path, undefined, false)`, что вообще не проверяло бит архива.
- Учётные данные процесса отрисовки больше не передаются через окружение дочернего процесса Host; они однократно внедряются при запуске через приватный канал, поэтому процессы того же пользователя не могут прочитать их из окружения процесса или аварийного дампа и выдать себя за процесс отрисовки.
- Гейт веб-доступа теперь **отказывает при отсутствии** учётных данных (раньше он пропускал, fail-open); запросы класса браузера больше не разрешаются молча.
- Глубокие ссылки `dsh-desktop://` диспетчеризуются по белому списку действий; неизвестные действия отбрасываются с одной строкой в журнале.
- Маскирование секретов для диагностики и журналов теперь охватывает формы base64url, поэтому учётные данные процесса отрисовки больше не могут быть выгружены.
- Маршрут выбора каталога использует ту же проверку loopback same-origin, что и маршрут настроек, вместо доверия к `Origin`, предоставленному клиентом.

Упаковка и выпуск:

- Контракт `asarUnpack` стабильной оболочки заново подтверждён на app-builder-lib 26.15.7: совпадения разрешаются относительно **пути упаковочного проекта**, поэтому три шаблона должны сохранять префикс `.desktop-build/payload/` из `files[].from`, чтобы сработать (`scripts/node-bin`, `assets` и `build` действительно распаковываются рядом с `app.asar`). Шаблоны остаются как были; новый тест выводит ожидаемый префикс из `files[].from` и проверяет его, падая при расхождении любой из сторон — раньше эта связка не была покрыта ни одной проверкой.
- CI получил покрытие упаковки стабильной оболочки, а `verify-layout` теперь требует совпадения версий: `version` в обоих рабочих пространствах должна совпадать с самым новым заголовком `CHANGELOG`.
- CI больше не переписывает `dsh-plugin-desktop-beta/package.json` на месте, чтобы пропустить AA smoke; вместо этой мутации добавлен явный скрипт `check:ci`, поэтому CI и локальный запуск совпадают.

Гигиена репозитория и цепочка поставок:

- Все сторонние Actions, используемые CI, закреплены на commit SHA (`actions/checkout`, `actions/setup-node`, `actions/cache`), а тег оставлен только завершающим комментарием для читаемости, поэтому перемещённый вышестоящий тег не может незаметно изменить то, что запускают гейты.
- Классификатор изменений больше не считает любой файл в `docs/` документацией: расширения, не относящиеся к документам, внутри `docs/` (`.js`/`.mjs`/`.json`/`.ts` и подобные) теперь запускают продуктовые гейты, и только настоящие форматы документации и `docs/schemas/*.schema.json` остаются исключениями.
- Из `vendor/agents-anywhere/` удалены шесть исторических tgz-файлов без ссылок (около 1,7 МБ), остался только закреплённый; README этого каталога больше не описывает удалённый путь `DSH_AA_SOURCE_REF=pinned`, а закрепляет через `provenance.pinnedCommit`.
- Файлы `nonead-dsh-desktop/README.md` и `README.zh.md` больше не содержат жёстко прописанную версию продукта (там было `2.1.3`); теперь они ссылаются на `version` из `package.json` и самую новую запись корневого `CHANGELOG`.
- Документация теперь указывает, что AppImage и deb для Linux x64 собирает только канал Beta, а стабильный канал поставляет для Linux запускаемый каталог; первой настоящей проверкой fuses и `onlyLoadAppFromAsar` служит задание CI `desktop-windows-stable` (`package:dir:stable`), поскольку локально их покрывают только модульные тесты.

## Известные проблемы

- Обновление из приложения в Linux только проверяет версию и никогда не загружает установщик; для обновления загрузите новый AppImage.
- Установщики Windows пока не проверяются криптографически: путь загрузки поддерживает серверный `installerSha256`, но конечная точка версии его не публикует, поэтому сравниваются только `ProductName` и `ProductVersion` из ресурса версии PE.
- Неинициализированный подмодуль `deepseek-harness` приводит к ошибке `corepack yarn check:layout`; обычная сборка, проверка типов и тесты не затронуты.
