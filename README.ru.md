## Что это

Nonead DSH Desktop объединяет локальный Web UI, службу Host и систему плагинов [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) в нативное настольное приложение. Исходный код апстрима работает **без изменений** и закреплён на конкретном выпуске; настольная оболочка отвечает за окна, трей, терминал, автообновление, несколько рабочих профилей и упаковку установщиков, а **сама подключается как плагин DSH** через тот же механизм композиции, который используют сторонние плагины.

Продукт — это не «переписанный клиент», а тонкий хост Electron плюс полноценная среда выполнения DSH:

| Слой | Расположение | Ответственность |
| --- | --- | --- |
| Настольная оболочка | главный процесс Electron | Блокировка единственного экземпляра, окна и материалы, трей и меню, разрешения, терминал, обновления, каталог данных, состояние профилей |
| Host | дочерний процесс в режиме Node | Загружает слой патчей профиля, запускает загрузку профиля апстрима, обслуживает Web-носитель, размещает сторонние плагины Host |
| Web-носитель | HTTP + WebSocket на loopback-адресе | Отдаёт официальный Web UI (по умолчанию на эфемерном порту) |
| Рендерер | изолированный BrowserWindow | Загружает официальный Web UI и опознаётся по заголовку с нативными учётными данными |

Оболочка и Host общаются ровно по одному каналу IPC дочернего процесса. Переключение профиля или режима уничтожает всё поколение Host и запускает новый дочерний процесс; состояние между поколениями не кэшируется. Рендерер не получает API Electron — он получает официальный Web UI плюс учётные данные доступа, сгенерированные оболочкой.

## Загрузка и установка

Официальные установщики доступны для Windows x64, macOS (Universal, включая Intel и Apple Silicon) и Linux x64 (AppImage). Дополнительное окружение не требуется. AppImage и deb для Linux x64 собирает бета-канал; стабильный канал в Linux выдаёт только запускаемый каталог, но не установщик.

| Платформа | Загрузка | Установка |
| --- | --- | --- |
| Windows x64 | [Скачать установщик](https://www.nonead.com/software/ndsh-desktop/downloads/windows) | Запустите установщик NSIS и следуйте подсказкам |
| macOS Universal | [Скачать DMG](https://www.nonead.com/software/ndsh-desktop/downloads/mac) | Откройте DMG и перетащите Nonead DSH Desktop в папку Applications |
| Linux x64 | [Скачать AppImage](https://www.nonead.com/software/ndsh-desktop/downloads/linux) | Сделайте файл исполняемым и запустите: `chmod +x Nonead-DSH-Desktop-*.AppImage && ./Nonead-DSH-Desktop-*.AppImage` |

Linux: в некоторых дистрибутивах нужно установить FUSE или запускать с `--appimage-extract-and-run`. Обновление внутри приложения в Linux **только проверяет версию и никогда не скачивает установщик**; для обновления скачайте свежий AppImage. Если нужен установщик для Linux, используйте бета-канал — стабильный канал в Linux выдаёт только запускаемый каталог.

Windows ARM64 доступен только как **экспериментальная сборка** и не раздаётся через ссылки для загрузки и автообновление выше: сама оболочка нативная arm64, но встроенная среда выполнения Python / Node / Office остаётся x64-полезной нагрузкой (исполняется через эмуляцию Windows), а артефакт ещё не проверялся на ARM-оборудовании. Соберите его самостоятельно командой из раздела [Обычные команды](#dev).

Пошаговое использование, профили и команды плагинов — в [руководстве пользователя](docs/user-guide.en.md); вопросы о платформах и границах применения разобраны в [FAQ](docs/faq.en.md).

## Возможности

| Возможность | Описание |
| --- | --- |
| Нативная настольная оболочка | Блокировка единственного экземпляра, нативные окна и меню, системный трей, значок в Dock; материалы окон зависят от возможностей платформы (macOS принимает `off`/`transparent` и по умолчанию использует `transparent`, Linux принимает оба, но всегда сводит к `off`, Windows — только `off`) |
| Локальное управление Host | Оболочка запускает дочерний процесс Host и владеет его жизненным циклом: сначала корректное завершение, через 10 с — `SIGTERM`, ещё через 5 с — `SIGKILL`; установка обновлений требует корректного завершения и в противном случае отклоняется |
| Официальный Web UI | Привязка только к `127.0.0.1`, порт по умолчанию выделяется системой; оболочка генерирует 32-байтовые случайные учётные данные для каждого поколения Host и передаёт их через заголовок `x-dsh-desktop-renderer` |
| Профили и первая настройка | Каталоги профилей находятся в `$DSH_HOME/profiles/<name>`; неинициализированный профиль при первом запуске сначала показывает мастер настройки Desktop (режим и материалы окна, магазин плагинов, уведомления, открытие в системном браузере по умолчанию, область веб-доступа) и только после него запускает Host |
| Браузер и доступ по LAN | «Открыть в браузере» влияет только на запуск системного браузера и не меняет область доступа; доступ по LAN — отдельный параметр, который также показывает текущий LAN-адрес |
| Встроенный магазин плагинов | DSH Community Market предлагает представления «обнаружение» / «доступные для установки» / «установленные» / «источники» с расширяемыми источниками каталога и проверенными адаптерами |
| Фирменная тема | `dsh-nonead-client-skin` поставляется вместе с установщиком и подключается профилем для каждого профиля, без отдельной установки |
| Автообновление | Проверка версии по фиксированному адресу `https://www.nonead.com/software/ndsh-desktop/version` с текущей версией, каналом и случайным идентификатором установки; Windows и macOS скачивают и устанавливают, Linux только проверяет |
| Опыт обновления | Карточка обновления показывает примечания к выпуску, полученные в ответе о версии, а меню трея и нативные диалоги бета-канала добавляют пункт «Показать полные примечания к выпуску»; «пропустить эту версию» сохраняется, поэтому автоматическая проверка по расписанию не предложит её снова; неудачную установку можно повторить и откатить к любому сохранённому снимку |
| Состояние окна и сеанса | Запоминает положение и размер окна; сохранённое положение восстанавливается, только пока оно пересекается с подключённым дисплеем, поэтому отключение монитора не уводит окно за пределы экрана |
| Глубокие ссылки и автозапуск | Поддерживаются ссылки `dsh-desktop://`, например `dsh-desktop://settings/general` сразу открывает настройки; переключатель автозапуска читает фактическое состояние ОС |
| Файл окружения | Строгая поддержка многослойных файлов `.env` дополняет отсутствующие переменные для дочернего процесса Host и никогда не переопределяет существующее окружение |
| Улучшения магазина | Магазин плагинов показывает превью медиа, отличных от изображений, и умеет устанавливать плагин по имени |
| Терминал и рабочий каталог | Оболочка предоставляет возможности терминала и рабочего каталога как службы Desktop для плагинов |
| Экспериментальные возможности | Онбординг по умолчанию включает магазин плагинов и Computer Use; речь, перевод, Agent Team и Ralph поставляются вместе со средой выполнения |

## Границы безопасности

| Граница | Фактическое поведение |
| --- | --- |
| Идентичность рендерера | Только запросы с учётными данными текущего поколения (`x-dsh-desktop-renderer`) считаются запросами рендерера Electron; при отключённом доступе из браузера все остальные запросы получают 403, а существующие WebSocket-соединения браузера разрываются |
| Передача учётных данных рендерера | Учётные данные существуют только в памяти главного процесса и процесса Host; Host при запуске принимает одну строку через свой **приватный stdin** и сразу закрывает канал, поэтому они не попадают ни в окружение дочернего процесса, ни в argv, ни в файл (прежняя реализация использовала переменную окружения, и процесс того же пользователя мог прочитать её из окружения процесса или дампа падения и выдать себя за рендерер) |
| Шлюз веб-доступа | Когда у Host нет учётных данных, он **отказывает** запросам браузерного класса и пишет одно предупреждение вместо того, чтобы их пропускать; обмен входа `/connect` и запросы только на чтение исключены в коде, а маршруты Market требуют учётные данные соединения даже для чтения |
| Доступ по LAN | **Аутентификации нет**: любой в той же сети, кто может подключиться к порту, откроет DSH и будет управлять этой машиной. Включайте только в полностью доверенных сетях |
| Проверка установщика | Путь загрузки поддерживает публикуемый сервером `installerSha256` и применяет его как жёсткое условие, но эндпоинт версии пока не публикует это поле; до тех пор Windows проверяет только `ProductName` и `ProductVersion` из ресурса версии PE, а macOS — идентичность бандла, встроенный манифест, подпись кода и Team Identifier; эта проверка идентичности есть только в стабильной оболочке, тогда как путь загрузки бета-оболочки проверяет лишь сигнатуру файла установщика и его размер, после чего сразу его выполняет |
| Ошибки в конфигурации плагинов | Патч с несовпадающим `id` пишет `entry not found` и пропускается; несовпадающий `name` пишет `name mismatch ... skipping`; но неверное имя службы в `inject` **не вызывает ошибку** — плагин остаётся в состоянии ожидания навсегда, а интерфейс показывает лишь необъяснимые HTTP 4xx |

## Структура репозитория

Корень — рабочее пространство Yarn `4.18.0` (`nodeLinker: node-modules`) со следующими участниками и обязанностями:

| Путь | Ответственность |
| --- | --- |
| `nonead-dsh-desktop/` | Рабочее пространство стабильного канала: собственная оболочка (профили и восстановление, управление окном, онбординг), мост Agents Anywhere и адаптеры Community Market, загрузчик Electron и упаковка |
| `dsh-plugin-desktop-beta/` | Рабочее пространство бета-канала: двойные грани Host/Client, загрузчик Electron, упаковка и тесты выпуска |
| `dsh-community-market/` | Продукт и дизайн безопасности встроенного магазина плагинов, контракт поставщика каталога, тесты и сборка |
| `dsh-community-fabric/` | RFC о взаимодействии сообщества: Manifest/Capability, Runtime/Presentation, композиция служб и диагностика происхождения |
| `dsh-nonead-client-skin/` | Фирменная тема оформления, поставляемая с пакетом; подключается через зависимость `file:` и не входит в список корневых рабочих пространств |
| `vendor/dsh-runtime/<version>/` | Vendored-пакеты среды выполнения DSH и `manifest.json` для каждого канала |
| `vendor/agents-anywhere/` | Vendored-пакеты моста Agents Anywhere |
| `patches/` | Патчи Yarn для упаковщика Electron, pnpm, `open`, `fs-ext`, подпроцесса DSH и другого |
| `scripts/` | Корневые шлюзы и скрипты выпуска (двуязычная документация, направление зависимостей магазина, vendored-среда выполнения, значки, layout, выпуск AA) |
| `docs/` | Документация продукта; в `docs/evidence/` хранятся измеренные записи о выпусках и установщиках |
| `deepseek-harness/` | Подмодуль апстрима только для чтения, закреплённый на `channels.beta.commit` в `upstream.json` |

**Для повседневной разработки подмодуль не нужен.** Среда выполнения хранится в репозитории, поэтому `corepack yarn install`, `build`, `typecheck`, `test`, `dev:*` и `dist:*` работают без него; он нужен только скриптам `upstream:*` (пересборка и упаковка среды выполнения). При этом `corepack yarn check:layout` проверяет коммит и рабочее дерево подмодуля, поэтому в неинициализированном клоне он неизбежно падает — это ожидаемо.

## Сборка из исходного кода

### Требования

- Node.js `^22.19.0` или `>=24.0.0`
- Корневой Yarn `4.18.0` через Corepack (не устанавливайте корневые зависимости через pnpm или npm)
- Git; нужен только для инициализации подмодуля апстрима при пересборке среды выполнения

```sh
git clone https://github.com/NoneadChina/Nonead-DSH-Desktop.git
cd Nonead-DSH-Desktop
corepack yarn install
corepack yarn dev:beta     # бета-рабочее пространство
# corepack yarn dev:stable # рабочее пространство стабильного канала (nonead-dsh-desktop)
```

Когда действительно нужен исходный код апстрима:

```sh
git submodule update --init --recursive
```

### Обычные команды

| Команда | Назначение |
| --- | --- |
| `corepack yarn dev:beta` / `dev:stable` | Запускает процесс разработки для соответствующего рабочего пространства (сначала проверяет закреплённый `dshmarket`, готовит артефакты AA и собирает магазин) |
| `corepack yarn build` | Собирает магазин, бета-рабочее пространство и рабочее пространство стабильного канала (также сначала проверяет закреплённый `dshmarket`) |
| `corepack yarn typecheck` | Проверка типов во всех трёх рабочих пространствах |
| `corepack yarn test` | Модульные тесты всех трёх рабочих пространств |
| `corepack yarn check` | Полная headless-проверка: layout, направление архитектуры, vendored-среда выполнения, двуязычная документация, коннектор AA, проверки каждого рабочего пространства |
| `corepack yarn check:ci` | Цепочка, которую действительно выполняет CI: то же, что `check`, но бета-рабочее пространство использует `check:ci` (без приостановленного в апстриме `verify:aa`) вместо перезаписи манифеста внутри CI |
| `corepack yarn check:layout` | Топология рабочих пространств, точные пины, подмодуль, vendored-среда выполнения, значки и проверки layout |
| `corepack yarn check:bilingual-docs` | Проверяет, что хеши Git blob, записанные в `*.i18n.yaml`, соответствуют документам |
| `corepack yarn check:vendored-runtime` | Сверяет `vendor/dsh-runtime/` с `upstream.json` |
| `corepack yarn market:prepare` / `market:check` | `market:prepare` переводит `dshmarket` на npm `latest` (только `resolutions`/зависимости двух настольных рабочих пространств и `yarn.lock`); `market:check` — офлайн-проверка согласованности, которую выполняет каждая сборка, и только `--latest` обращается к сети |
| `corepack yarn aa:prepare-release` / `aa:check` | Собирает или проверяет артефакты выпуска Agents Anywhere |

| `corepack yarn dist:win:beta` / `dist:mac:beta` / `dist:win-portable:beta` | Готовит артефакты выпуска для нужной платформы |

Соглашения:

- Корневые `build`, `dev:*` и `dist:*` сначала запускают `corepack yarn market:check`: проверка идёт офлайн и сверяет согласованность закоммиченной версии `dshmarket`, lockfile и патча совместимости, не обращаясь к сети и не переписывая манифесты. Для перемещения этого пина человек должен выполнить `corepack yarn market:prepare` и закоммитить версию, lockfile и патч вместе.
- `nonead-dsh-desktop` и `dsh-plugin-desktop-beta` — **отдельные рабочие пространства**: общие изменения должны попасть в оба с сохранением заявленных различий; перед выпуском запустите `corepack yarn check` и проверки каждого рабочего пространства.
- После правки `README*.md` или `CHANGELOG*.md` на любом языке обновите хеши Git blob в соответствующем `*.i18n.yaml` (снимайте их через `git hash-object`), иначе `check:bilingual-docs` упадёт.
- `corepack yarn check:layout` требует инициализированного подмодуля; в полностью headless-окружении проверяйте бизнес-код через `typecheck` / `test` / `check` соответствующего рабочего пространства.
- **CI не должен позволять проверяемому коду решать, что запускать**: задание `changes` восстанавливает `scripts/` из **базовой версии pull request** перед запуском классификатора и шлюзов документации и магазина (документы по-прежнему берутся из рабочего дерева); у `workflow_dispatch` базовой версии нет, поэтому он откатывается к копии из head с предупреждением. CI выполняет `corepack yarn check:ci` (= локальный `check` без `verify:aa`) вместо перезаписи `dsh-plugin-desktop-beta/package.json` во время выполнения.
- **Согласованность версий — часть шлюза**: `scripts/verify-layout.mjs` требует, чтобы `version` обоих рабочих пространств совпадала с самым новым заголовком `## <version> — <date>` в `CHANGELOG.md`, поэтому пропуск любой стороны при выпуске приводит к сбою.

<a id="release"></a>

## Выпуск и обновления

- **Две продуктовые линии**: выпускаются двумя настольными рабочими пространствами. Установщики бета- и стабильного канала различаются идентификатором бандла, префиксом артефакта и каналом обновления, и их нельзя смешивать.
- **Протокол каналов**: проверка версии обращается к `https://www.nonead.com/software/ndsh-desktop/version`, сообщая текущую версию в `X-DSH-Desktop-Version`, `stable` / `beta` в `X-DSH-Desktop-Channel` и локально сгенерированный и сохранённый случайный UUID в `X-DSH-Desktop-Installation-Id`. Загрузка установщика передаёт `channel` и `X-DSH-Desktop-Target-Version`, но никогда — идентификатор установки или текущую версию.
- **Соблюдение канала**: ответ сервера должен повторять канал; стабильный канал принимает только обычный SemVer, бета-канал — только `-beta.N`, и клиент никогда не скачивает в обход канала.
- **Согласованность версий**: загруженный артефакт, сопоставление «версия → файл» в адресе прямой загрузки и версия, которую сообщает эндпоинт, должны совпадать — при несовпадении возвращается 404, а не устанавливается неверная версия.
- **Условия выпуска**: сначала выполните `corepack yarn aa:prepare-release`; если выпуск включает новый `dshmarket`, человек должен также выполнить `corepack yarn market:prepare` и закоммитить его. Команды распространения для Windows дополнительно проверяют артефакты AA через `--verify-release`.

<a id="plugins"></a>

## Экосистема плагинов

Плагины расширяют DSH — модели, инструменты, интерфейс и рабочие процессы суть плагины, которые складываются как кубики. Nonead DSH Desktop не изменяет исходный код апстрима и не является жёстко зашитой оболочкой: закреплённый апстрим работает как есть, а сама настольная оболочка подключается по тому же правилу «всё есть плагин».

Авторам плагинов достаточно трёх вещей:

1. **Обычные плагины DSH** разрабатываются точно так же, как в любой среде DSH, — см. [разработку плагинов](docs/plugin-development.en.md).
2. **Службы Desktop** (`desktopProfiles`, `desktopPnpm`, …) позволяют плагинам просматривать или переключать профили и устанавливать, обновлять или удалять плагины — см. [службы плагинов Desktop](dsh-plugin-desktop-beta/docs/plugin-services.md).
3. **Композиция и патчи**: профиль собирается наложением слоёв патчей, где `id` совпадает с существующей строкой, а `insert` добавляет новые строки; учитывайте три «тихо бездействующих» сценария отказа в разделе [Границы безопасности](#security).

Видение и три принципа — в [предложении об экосистеме плагинов DSH](docs/plugin-ecosystem.en.md); общественное предложение о едином контракте плагинов — [Community Fabric](dsh-community-fabric/README.md).

Если вам нужен только DeepSeek Harness из командной строки или вы хотите работать над его ядром, обратитесь к репозиторию апстрима.

<a id="limits"></a>

## Известные ограничения

- **Обновление внутри приложения в Linux только проверяет версию** и никогда не скачивает установщик; для обновления скачайте свежий AppImage.
- **Windows ARM64 поставляется как экспериментальная сборка**: `dist:win:stable` по умолчанию создаёт только установщик x64; для arm64 нужен `DSH_PACKAGE_ARCH=arm64` (в паре с `DSH_PACKAGE_OUTPUT_DIR` для отдельного каталога вывода). Оболочка нативная arm64, а встроенная среда выполнения остаётся на x64-полезной нагрузке (эмуляция Windows), сборка под другую архитектуру пропускает дымовые тесты, требующие запуска, а канал обновления сейчас содержит единственный артефакт `windows`, поэтому не может раздавать x64 и arm64 одновременно.
- **Установщики Windows пока не проверяются криптографически**: путь загрузки поддерживает серверный `installerSha256`, но эндпоинт версии его не публикует, поэтому сейчас сравниваются только `ProductName` / `ProductVersion` (только стабильная оболочка; бета-оболочка проверяет лишь сигнатуру и размер установщика, а затем сразу его выполняет).
- **Доступ по LAN не имеет аутентификации** — он передаёт DSH этой машины всем в том же сегменте сети.
- **Неверное имя службы в `inject` у плагина отказывает молча** — плагин навсегда остаётся в состоянии ожидания и проявляется только как HTTP 4xx.
- Локальный `yarn install` может переписать отпечаток содержимого `dsh-nonead-client-skin` в `yarn.lock` (не воспроизводится между машинами); **не коммитьте такие локальные изменения lockfile**.
