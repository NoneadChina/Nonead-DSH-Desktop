# DSH 插件生态倡议书

[English](plugin-ecosystem.en.md) | 中文

DSH Desktop 不只想做一个好用的桌面壳。它想证明一件事：**当宿主把"怎么组合插件"讲清楚时，生态自己会长出秩序**。这份文档是倡议，不是规范；规范在 `dsh-community-fabric`，而那里目前仍是 Draft。

## 我们的愿景

一个健康的插件生态应该同时满足三个条件，缺一个都会退化：

- **开放**：任何人不经审批就能写插件、发布插件、被别人装上。
- **可组合**：两个互不相识的插件能同时装上并各自工作，不需要知道对方存在。
- **可持续**：宿主升级不会成批打死插件，插件作者也不用追着宿主的每个内部改动跑。

这三件事不会自动发生。它们需要有人先把边界画出来，再用产品自己当第一个守规矩的用户。

## 我们倡导的三条原则

**组合优先。**插件声明"我需要什么"，宿主负责满足；插件不要自己去找、去改、去绕过。需要平台能力时用注入与补丁声明，而不是去读别人的配置文件。

**声明清晰。**能被机器读的才叫声明。`dsh.bundle.patch`、`dsh.client`、`inject`、manifest 字段——这些是契约；README 里的说明是文档，不是契约。两者都要有，但不能互相替代。

**兼容优先。**同一份代码在没有桌面的普通 DSH 里也必须能跑。做不到就说明它不该是插件，应该是一个独立应用。

## 桌面壳是第一个范例

我们不是先写规范再找用户，而是反过来：**先把桌面壳按这套原则做完，再把它当成范例交出去**。

具体到实现：

- 桌面壳全部能力通过 Cordis service 与 profile 补丁接入，没有一处需要改上游。
- 对插件只公开两个 Host service，其余内部件明确标注为不可依赖。
- 兼容 Desktop 与普通 DSH 被写成硬要求，而不是"建议"。
- 补丁写错有三种不同的失效方式，我们把它们逐条写进文档——包括那个**没有警告**的。

一个自己都不遵守组合原则的宿主，没有资格倡议别人遵守。

## 活文档，社区共建

这份文档是活的。任何一条原则如果和代码冲突，是文档要改，不是代码要迁就文档。发现"文档说支持、实际不支持"，那是 bug，请开 issue。

同样地，`docs/architecture.md` 与 `docs/plugin-development.md` 描述的是**当前实现**；`dsh-community-fabric` 描述的是**打算成为标准的东西**。两者混读是这一带最常见的误解来源。

## 插件市场：让约定成为有利的选择

市场不是生态的裁判，是生态的**成本结构**。`dshmarket` 依赖固定在 `1.66.47`（桌面补丁基于该版本重建），作为普通 DSH 插件随 Desktop 分发——它自己声明 `dsh.bundle.patch` 与 `dsh.client`，在官方 Plugins 页面与内置能力并列，安装、启用、禁用、卸载都交给官方插件管理器。

`dsh-community-market`（`0.1.0-dev.0`）是社区市场的骨架：4 篇双语文档（目录适配器指南、目录提供方契约、安装与卸载、市场壳）、JSON Schema、示例，以及按名安装与非图片媒体预览这两个已经落地的行为。它还不完整，但边界已经写下来了。

约定的价值在于：**遵守约定的人获得更低的分发成本**。市场条目遵守 schema，就能被索引、被预览、被一键安装；不遵守的插件不是"被封杀"，只是享受不到这些。

## 从倡议走向可测试的 contract

倡议如果不能被测试，迟早会退化成口号。所以下一步是把原则变成 contract：

- `dsh-community-fabric` 已有 4 份 Draft RFC：manifest 与 capability/event（0001）、运行时呈现与调用传输（0002）、service provider 与组合（0003）、来源校验与诊断（0004）。全部中英双语，全部还是 Draft **不是已发布标准**。
- capability 用于兼容判断、用户确认与审计，**它不是安全沙箱**。声明"我只读文件"不会让运行时真的只给它读权限。
- 目录收录不等于安全审核。市场里出现一个插件，只说明它符合条目格式。

写插件时按现状写（本文与 `plugin-development.md`），需要更远的形状就去 RFC 里讨论——不要按 Draft 实现生产代码，也不要把 Draft 当成既成事实去引用。

## 如何参与

- **写插件**：从 [插件开发](plugin-development.md) 开始，先做能跑在普通 DSH 里的那一版。
- **提 RFC**：`dsh-community-fabric` 的 RFC 目录对所有人开放，反对意见比赞成更有价值。
- **写文档**：发现文档与代码不一致，改文档或开 issue，两者都算贡献。
- **用起来**：真实使用是唯一有效的验收。装不上的插件、说不清的报错，都是生态要修的地方。
